# Проверка 0.2.1 — 9 сентября 2026

На HA 2026.8.3 и 2026.9.1 / HAP-python 5.0.0: 29 тестов на каждую версию.
Новые регрессии проверяют 0, 0.0, 1, 100 в HA и фактические значения
On/Brightness в сериализованном HAP accessory и getter callbacks.
Также проверены установка нуля из HomeKit, On без яркости, возврат к 25
и отсутствие команд питания TV. Невалидная number продолжает выставлять StatusFault.
Три новых сценария нуля падали на 0.2.0 и проходят после исправления.

При нуле новый контракт — Off/0. Смена service/IID и пересопряжение не требуются.
Скриншоты пользователя подтверждают исходное расхождение HA 0.0 / Apple Home 100%,
но реальное отображение после установки 0.2.1 ещё не проверено.

# Проверка 0.2.0 — 7 сентября 2026

| Home Assistant | HAP-python | Python / платформа | Результат |
|---|---|---|---|
| 2026.8.3 | 5.0.0 | 3.14.7 / macOS ARM64 | 24 passed, 1 warning |
| 2026.9.1 | 5.0.0 | 3.14.7 / macOS ARM64 | 24 passed, 1 warning |

Использованы настоящие установленные пакеты HA/PyHAP. Проверены Television + linked Lightbulb,
питание отдельно от подсветки, валидация number, синхронизация HA → HomeKit,
отбрасывание команд при off и после цикла off/on, остановка подписок,
отсутствие влияния на другой TV, Inputs и неизвестный ActiveIdentifier.
Дополнительно проверены отказ при изменённой сигнатуре API и сохранение/загрузка IID
через настоящий HA Store во временном каталоге. Сетевой driver остаётся тестовым.

В обеих версиях используется HAP-python 5.0.0 согласно manifest штатного HomeKit.
Статический анализ исходников: ruff, без ошибок. ZIP собирается из allowlisted каталога
компонента с лицензией; контрольная сумма SHA-256 лежит рядом.

Единственное предупреждение адаптера — DeprecationWarning штатного HA HTTP-класса.
Первая попытка в общей среде конфликтовала с autouse fixtures PHACC; итоговый запуск
изолирован от посторонних pytest-плагинов:

```sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=. python -m pytest -p pytest_asyncio.plugin tests -q
```

Не проверены: реальный HA Container Linux amd64, полный bootstrap с пользовательским YAML,
mDNS, pairing iPhone, фактические команды LG, отображение Apple Home и сохранение pairing
после обновления на NAS. Проверка временного IID Store не заменяет эти проверки.
GitHub Actions: HACS и hassfest прошли после добавления локальной иконки;
матрица поведения также прошла для исходного кода релиза.
Запуски: https://github.com/VladLikov/lg_tv_homekit/actions
Это проверки Linux CI, а не пользовательского NAS или iPhone.

Добавление новой версии в compatibility.py требует полного прогона этой матрицы
и просмотра изменений используемых HomeKit-классов. Проверка сигнатур дополняет тесты,
но сама по себе не доказывает семантическую совместимость.
